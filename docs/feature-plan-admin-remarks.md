# 機能設計たたき台: 管理者追記の通知と対応ステータス管理

状態: **未実装の設計たたき台**(2026-11-16時点)。実装は仲さんの改修指示を受けてから着手する。

## 目的
管理者が日報の備考に追記(注意事項・感想・疑問点など)した際、記入者へ通知する。
対応を求める内容については、記入者の「対応済み」が管理側から分かるようにする。

## 仕様(確定案)

### 1. タグ表示と通知の消え方(タイプ別)
| タイプ | 管理者が追記時に選択 | タグの色 | 消え方 |
|---|---|---|---|
| 情報共有 | 感想・参考情報など | 青/グレー | 記入者が開いて確認したら消える |
| 対応依頼 | 注意事項・疑問点など対応を求めるもの | オレンジ/赤 | 記入者が「対応済み」を押すまで消えない |

### 2. 対応依頼のステータス管理(管理側ビュー)
- 記入者の確認操作: 日報を開く → 「対応済み」ボタンを押す(任意で一言返信を添えられる)
- 管理ダッシュボードに「対応依頼中」の一覧と件数を表示(押し忘れの見逃しゼロ)
- 対応済みになった追記は履歴として日報に残る(消さない)

### 3. データ設計(work_reports にフィールド追加)
- `adminNotes`: string(管理者追記本文)
- `adminNotesType`: 'info' | 'require_action'
- `adminNotesStatus`: 'unread' | 'read' | 'done'
- `adminNotesRespondedAt`: timestamp(対応済み押下時刻)
- `adminNotesResponse`: string(任意の一言返信)
- **Firestoreルールの変更は不要**(管理者のupdate・本人による自分日報のupdateは既存ルールで許可済み)

### 4. メール通知(案B・実施要否は未決)
- 保存時に既存Azure関数(nakano-scan-proxy)へ新エンドポイント `/api/notify` を追加し、`user.email` 宛に送信
- 前提条件: Azure関数ソースの取得+発行プロファイルの提供、メール基盤の選択
  (Azure Communication Services Email / SendGrid無料枠 / M365 SMTP)

## 未決事項(改修指示時に確定)

2. メール通知(案B)の要否とメール基盤の選択
